# 可靠性、验证与发布

当前版本由根目录 `release.json` 定义。0.4.16 补充桌面时钟修复；此前的数据、事务、缓存和发布优化继续保留。现场验收保持单独记录。

## 桌面时钟（0.4.16）

桌面时钟绘制在静态壁纸中，以分钟为显示单位。客户端每秒检查是否需要更新，仅在分钟、分页或内容等状态改变时重新生成画面。同一分钟的空闲检查不会反复写壁纸，暂停期间也不重复保存状态。

- 本地展示与网络同步使用独立等待标志。慢快照、图片、心跳及回传不再阻塞下一次本地时钟检查；收到新内容后直接尝试展示。
- 调度与在线后的走时使用单调时间，检测 Windows 时间突变并重新校时。快照响应到达时记录时间锚点，图片下载耗时不计入时差；200 和 304 都能校时。新服务返回 `X-ClassGlow-Time`，旧服务使用快照正文或 HTTP `Date` 兼容。
- 目标屏幕全屏期间保留保护，另一屏全屏不再阻塞可见目标桌面。退出全屏、解锁、唤醒及恢复展示后重新检查当前时间；不补播休眠期间的旧分钟。
- WebView2 材质创建、加载和捕获共用 10 秒期限，退出清理最多另等 3 秒。失败后使用原生兼容材质，10 分钟内不反复创建；未完成的创建仍被跟踪，迟到控制器会关闭。
- 状态页增加画面生成和最近校时时间。手动诊断增加展示检查时间、阻塞原因与最近渲染耗时，便于区分网络仍在线、画面未更新以及主动保护。

2026-11-06 在 106 只读核对：唯一在线设备仍为 0.4.11。该版本仅允许桌面或本程序处于前台时更新，普通窗口获得焦点时，即使桌面时钟仍可见也会延后；此限制在 0.4.12 已放宽。服务器升级不会替换教室客户端，需在教室电脑覆盖安装新客户端。短时观察时该设备的画面时间仍在推进，不能据此证明客户现场已恢复。完整证据与测试边界见 [验证记录](VERIFICATION.md)。

0.4.16 不新增数据库迁移。发布前仍须分发与版本一致的 Windows 安装包；本地构建成功不代表生产服务器或教室设备已经升级。

## 数据和事务

- 首页及设备同步只包含已发布且展示尚未结束的内容；全部未来发布均进入离线缓存，不按条数截断。历史作业、完成/撤回记录和修改历史通过分页查询与导出保留。
- 内容增加 `display_from`、`display_until`、`created_at` 索引列，由业务 JSON 时间派生。迁移分批回填，按班级、状态、结束时间及创建时间建立索引。
- SQLite 使用 WAL。GET 纯查询不获取写事务锁；设备快照负责命令状态推进与联系时间，仍使用写事务。控制台 GET 计算命令过期状态，持久化由设备同步推进。
- 写请求保留原有账号、班级、幂等和修订锁。数据库依赖明确使用函数作用域，先提交，再发成功响应。提交失败返回带问题编号的 503，保留输入和幂等重试语义。
- SSE 鉴权采用短时只读会话。继续使用单 API 进程；增加进程数前，仍须将通知与限流状态移至共享服务。

## 图片、缓存和兼容

图片存入 `class_assets`，按班级与 SHA-256 去重。布局保存 `asset:<摘要>` 引用，替换布局时清除该班不再引用的素材。读取必须通过班级成员或绑定设备鉴权，其他班级不能仅凭摘要读取图片。

新 Web 和 Windows 客户端通过 `X-ClassGlow-Assets: 1` 协商独立图片，校验摘要与大小；图片未齐或损坏时保留上个完整模型/快照。Windows 完整缓存继续由 DPAPI 保护，重启可直接复用快照中的图片。旧客户端继续收到内嵌图片；能力标志进入 ETag，升级后不会被旧 304 遮住。

原生一致性数据库备份同时包含素材；班级 JSON 导出会展开素材，仍是独立可读文件。WAL 模式下继续使用现有备份命令，不把运行中的 SQLite 主文件单独复制当作完整备份。

## 多端登录和页面状态

默认允许 5 个登录设备，`KANBAN_SESSION_LIMIT` 可调整为 2–20。同一浏览器重新登录替换该浏览器的会话；达到上限时淘汰最早的有效登录。随机浏览器标识不是硬件指纹。升级保留现有有效会话。

“我的账号 → 登录设备”可查看登录时间，单独退出设备或退出其他设备。改密、重置密码、安全冻结和账号停用仍按原规则撤销会话。迟到的旧账号刷新不能覆盖新账号资料。

工作台 URL 保存班级、页面和记录筛选/页码，刷新、前进和后退可恢复位置；权限由当前账号重新校验。设计室、后台、提醒编辑及相关样式按需加载，画布撤销重做提取为独立模块。

## 诊断

- API 返回 `X-Request-ID` 与 `Server-Timing`。日志仅记录方法、路由模板、状态、耗时、问题编号和异常类型，不记录 URL 参数、口令、凭证或正文。
- 后台首页显示请求数、服务错误数和各接口最近 128 次请求的 P95，可导出诊断 JSON。指标保存在进程内，重启清空。
- Windows“导出诊断”只导出版本、运行环境、同步时间、版本/分页/暂停状态等白名单字段，不导出凭证、教学快照、图片或用户文件路径，不自动上传。

## 迁移和发布

新增迁移 `f3748d52ba16` 与 `f4859e63cb27`：回填时间索引、会话标识，分离既有布局图片。账号、草稿、正式记录、设备绑定和同步世代均保留，不主动撤销已有授权。

1. 在维护窗口执行一致性备份，保留备份和当前部署提交。
2. `classglow update` 支持手动跟随 main；`classglow update --release v版本号` 指定稳定标签。构建时旧服务继续运行，停止服务前检查镜像版本及唯一迁移入口。
3. 脚本停写、备份、迁移并检查健康；原部署提交另存 `.deploy/previous-commit`。手工部署先运行 `uv run alembic upgrade head`，再启动服务。
4. 分发对应 EXE 和同名 SHA-256 JSON 清单，更新 `KANBAN_CLIENT_DOWNLOAD_URL`。服务先更新而仍分发旧包时，下载接口按版本化文件名报告实际安装包版本。
5. 自动更新仅选择 main 历史中的 `vX.Y.Z` 标签，默认仅在北京时间 02:00–05:00 部署。`KANBAN_UPDATE_WINDOW=22-02` 可跨午夜；`always` 表示明确允许任意时段。稳定标签应在 CI 通过后创建。

失败后自动更新暂停。保留当前库、迁移日志和失败前备份，先诊断后恢复。本次图片迁移支持反向迁移；恢复旧代码前应在隔离库验证逆迁移，不能直接让旧代码读取素材引用，也不能用旧备份覆盖更新后产生的教学内容。整体备份还原继续使用既有流程，更换同步世代并重新登录/绑定。

改版本时运行 `uv run python -m scripts.release_check --write`，随后 `uv lock`。后端模型改变后运行 `uv run python -m scripts.generate_contracts`。CI 检查请求类型、JSON Schema 和三端协议常量是否漂移；安装包构建先执行版本与契约检查。

## 自动化验证

```powershell
uv run pytest -q
uv run ruff check backend scripts
uv run python -m scripts.release_check
uv run python -m scripts.generate_contracts --check
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run test:e2e
dotnet build desktop/ClassroomBoard/ClassroomBoard.csproj -c Release
dotnet desktop/ClassroomBoard/bin/Release/net10.0-windows/ClassroomBoard.dll --self-test --output .qa/desktop
dotnet desktop/ClassroomBoard/bin/Release/net10.0-windows/ClassroomBoard.dll --reliability-check --output .qa/reliability
dotnet desktop/ClassroomBoard/bin/Release/net10.0-windows/ClassroomBoard.dll --clock-check --output .qa/clock
uv run python -m scripts.verify_client
uv run python -m scripts.load_check
```

浏览器及联调服务使用随机临时数据库和回环端口。端口被占用即拒绝复用，不向现有服务写入验收账号。覆盖提交失败、并发幂等重试、写事务期间读取、历史积累、未来离线展示、素材授权/校验/备份/迁移、多端撤销和手机流程。

本机短时检查为 20 个终端、180 次混合请求，零错误，P95 约 508 ms，最长约 855 ms；环境为回环网络、单进程 SQLite WAL。该数据不代表公网容量或低配教室性能。
